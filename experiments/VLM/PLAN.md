# VLM 오류 분석 계획(초안, 승인 전. API 호출 없음, 2026-11-26)

공식 안내문(메인) "모델 평가 및 VLM 기반 오류 분석"을 따른다. VLM 설명은 원인 확정이 아니라 **가설 재료**다(O-05, 안내문).

## 대상(규칙으로 고정, `src/vlm_select.py` → `candidates.csv`, 55장)

- 데이터: **공식 Validation**, 선정 모델 SEL-A-s43(D-031) 예측(`experiments/E06/pred_val_SEL-A-s43.csv`, Val Macro F1 0.8782, 오답 163장). Test는 쓰지 않는다.
- 오분류 40장: 클래스별 상한(덤벨 로우·데드리프트·바벨 로우 각 8, 런지 5, 라잉 레그 레이즈·바이시클 크런치 각 4, 나머지 1). 클립당 1장, 확신도 높은 오답부터, 카메라를 돌아가며.
- 정답 15장: 클래스마다 1장(그 클래스 오답이 많은 카메라의 맞힌 사진), 2·7·9는 1장 더.
- 오답이 없는 클래스(니푸쉬업, 딥스, 로잉머신)는 정답 사례만.

## 호출 방식(제안)

1. **블라인드 호출**: 정답·예측을 알려 주지 않고, 12개 운동 목록만 주고 "무엇으로 보이는지 + 근거 + 확신"을 묻는다. VLM도 같은 사진을 헷갈리는지 본다.
2. **설명 호출**: 정답과 모델 예측을 알려 주고 안내문 항목을 묻는다(주요 시각 특징, 정답·예측 클래스를 가르는 특징, 오분류와 관련 있을 수 있는 이미지 특성, 배경·밝기·해상도·대상 형태, 사진만으로 판단하기 어려운 점).
- 응답은 JSON으로 받고 `experiments/VLM/results.jsonl`에 원문 그대로 저장. 기록 표는 안내문 항목(이미지 ID, 실제·예측, Correct/Incorrect, 주요 특징(육안 + VLM), 가능한 오류 요인, 추가 확인 사항).
- 입력 이미지는 원본 384×216 그대로(축소본이라 비용이 작음).

## 상한·비용(승인 필요)

- 호출 최대 110회(55장 × 2). 코드에 호출 수 상한과 누적 비용 상한을 둔다. U-08 초안 상한은 $3. 학원 키는 초과해도 자동 차단이 없다.
- 모델: 이미지 입력이 되는 OpenAI 모델 중 하나. 실제 사용 가능 여부와 단가는 최소 호출 1회로 확인한 뒤 확정한다.
- 필요한 것: `openai` 패키지 추가(`uv add openai`, 승인 사항), 사용자가 `fitness/.env`에 `OPENAI_API_KEY` 직접 입력(키를 채팅으로 주고받지 않음).
- AI Hub 이미지를 외부 API로 보내는 것은 공식 안내문이 요구하는 절차다. 공개 저장소에는 이미지와 응답 속 이미지 파일을 올리지 않는다(응답 텍스트는 올려도 됨).
